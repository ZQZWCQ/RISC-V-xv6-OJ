# S01 环境打通操作清单

> 目标读者：本项目开发成员
> 前置条件：一台可安装虚拟机的个人电脑
> 预计总耗时：3~5 小时（主要消耗在镜像构建与下载）

---

## 一、目标与验收标准（DoD）

**目标**：在自己机器上从零跑通「编译 → QEMU 启动 → `make grade` → 得到分数」的完整链路，并取得**真实性能数字**。

| # | 验收项 | 状态 |
|---|---|---|
| 1 | 容器内 `make qemu` 能看到 `init: starting sh` | `[ ]` |
| 2 | `./grade-lab-util -v --toolprefix riscv64-elf-` 能输出 `Score: x/y` | `[ ]` |
| 3 | 实测三个数字：全量编译耗时 / 单次 grade 总耗时 / 单测试平均耗时 | `[ ]` |
| 4 | 三种失败路径的真实表现（空补丁 / 错误基线 / 编译错误） | `[ ]` |
| 5 | 确认 `/dev/kvm` 是否可用、QEMU 是否需要 `--privileged` | `[ ]` |

> ⚠️ **S01 不写任何业务代码。** 唯一产出是「这条链路能跑 + 耗时数字」。这些数字决定后续全部容量设计与超时阈值。

## 二、阶段 0：宿主准备（约 30 分钟）

- 检查 CPU 虚拟化：任务管理器 → 性能 → CPU → 确认「虚拟化：**已启用**」
- 虚拟机软件：VMware Workstation Player（个人免费）
- 建议虚拟机配置：**4 核 / 8 GB 内存 / 60 GB 磁盘**
- **开启嵌套虚拟化（关键，决定 `/dev/kvm` 是否可用）**
  - VMware：虚拟机设置 → 处理器 → 勾选「虚拟化 Intel VT-x/EPT 或 AMD-V/RVI」
  - VirtualBox：`VBoxManage modifyvm "<虚拟机名>" --nested-hw-virt on`

## 三、阶段 1：安装 Ubuntu Server（约 40 分钟）

- 镜像版本：**Ubuntu Server 24.04 LTS**
- 安装时**勾选 OpenSSH server**（之后可从宿主机 SSH 进入，便于复制粘贴命令）
- 安装完成后：

```bash
sudo apt update && sudo apt upgrade -y
grep -c -E 'vmx|svm' /proc/cpuinfo    # 大于 0 表示虚拟化已透传
ls -l /dev/kvm                        # 存在即表示 KVM 可用
```

## 五、阶段 3：安装 Docker（约 15 分钟）

> ⚠️ **不要使用 `apt install docker.io`** —— Ubuntu 仓库中的它是 snap 包，存在已知问题。使用 Docker 官方 apt 源：

```bash
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker $USER     # 之后需退出重新登录
docker run --rm hello-world
```

## 七、阶段 5：构建评测镜像（约 30~60 分钟，取决于网络）

课程自带 `Dockerfile` 有两处在国内会非常慢：Arch 的 pacman 使用国外源、从 GitHub 下载 gdb-dashboard。

**改良版 `Dockerfile.s01`**（置于仓库根目录）：

```dockerfile
FROM archlinux:latest

# 换用国内镜像源（关键，否则 pacman 会非常慢）
RUN echo 'Server = https://mirrors.tuna.tsinghua.edu.cn/archlinux/$repo/os/$arch' > /etc/pacman.d/mirrorlist

RUN pacman-key --init && pacman -Syu --noconfirm

RUN pacman -S --noconfirm gcc make perl wget git python python-pip

RUN pacman -S --noconfirm riscv64-elf-gcc riscv64-elf-binutils riscv64-elf-gdb riscv64-elf-newlib qemu-emulators-full

WORKDIR /mnt
CMD ["bash"]
```

```bash
docker build -f Dockerfile.s01 -t rv6judge:s01 .
```

> 说明：此版**刻意去掉了 gdb-dashboard 的下载**，S01 不需要 GDB 调试，后续需要时再加回。
> `qemu-emulators-full` 是包含全部架构 QEMU 的大包（数百 MB），下载慢属正常现象。

## 八、阶段 6：跑通手工链路（核心，约 30 分钟）

**先验证「不加特权能否运行」** —— 这直接决定后续的安全设计：

```bash
docker run --rm -v ~/rv6/xv6-oslabs-hitsz:/mnt -w /mnt rv6judge:s01 \
  bash -c "make clean && time make"
```

编译通过后再启动：

```bash
docker run --rm -it -v ~/rv6/xv6-oslabs-hitsz:/mnt -w /mnt rv6judge:s01 bash
# 容器内执行：
make qemu
#   看到 "init: starting sh" 与 "$" 提示符即成功
#   退出 QEMU：按 Ctrl+A，松手，再按 X
```

> ⚠️ 若 QEMU 启动失败，**不要急于加 `--privileged`**，按序排查：
> 1. `qemu-system-riscv64 --version` —— 确认已安装
> 2. 缺少 `/dev/kvm` 不影响：QEMU 会自动回退到 TCG 纯软件模拟
> 3. **仅在确认是权限问题时**，才参照课程 Makefile 的做法加 `--privileged`

## 十二、预判会踩的坑

| 现象 | 原因 | 处理 |
|---|---|---|
| pacman 下载极慢 | 使用了国外源 | 换清华源（上方 Dockerfile 已处理） |
| `docker build` 长时间卡在 `pacman -Syu` | Arch 为滚动更新，包体积大 | 耐心等待，或临时加 `--network=host` |
| QEMU 无输出 | 串口未接 | 使用课程 Makefile 的 `make qemu`（已含 `-nographic`） |
| `make grade` 报 Python 错误 | 镜像内 Python 版本较新 | 课程已提交过 Python 兼容补丁；若仍报错，保留 traceback |
| `/dev/kvm` 不存在 | 宿主未开启嵌套虚拟化 | 回到阶段 0 |

# 契约 C1：后端 ↔ 评测内核

> 状态：草案 v0.1（待 S01 实测后定稿）
> 双方：`services/api`（调用方） ↔ `services/judge`（实现方）
> 变更前必须先改本文件

---

## 1. 交互方式

**命令行 + JSON 文件**，不使用 HTTP。

理由：评测必须能在容器里独立运行、独立测试；后端只需起一个子进程。

```
rv6judge run \
  --patch   /in/commit.patch \
  --lab     syscall \
  --out     /out/result.json \
  --workdir /work \
  --timeout 900
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `--patch` | 是 | 补丁文件路径 |
| `--lab` | 是 | 实验标识：`util` / `syscall` / `lock` / `pgtbl` / `lab5` |
| `--out` | 是 | 结果 JSON 写出路径 |
| `--workdir` | 否 | 工作目录，默认临时目录 |
| `--timeout` | 否 | 整次评测总超时（秒），默认 900 |
| `--submission-id` | 否 | 调用方透传，原样回填到结果 |

---

## 2. 退出码

| 码 | 含义 |
| --- | --- |
| `0` | **评测流程正常完成**（注意：**不代表满分**） |
| `10` | 预检未通过，未进入评测 |
| `11` | 编译失败 |
| `12` | 运行超时 |
| `20` | 平台内部错误（容器起不来等） |

> **注意**：课程判分脚本 `gradelib.py` 在未满分时执行 `sys.exit(1)`。
> 因此**绝不能用退出码判断成绩**——分数一律从 `--out` 的 JSON 中读取。

---

## 3. 输出 JSON

```json
{
  "schema_version": 1,
  "submission_id": "调用方透传，可为空",
  "lab": "syscall",
  "base_ref": "syscall-26-fall-v2",
  "stage": "done",
  "verdict": "scored",
  "score": { "earned": 80, "possible": 100 },
  "self_reported_score": "Score: 80/100",
  "failure_class": null,

  "precheck": {
    "passed": true,
    "checks": [
      {
        "code": "patch.contains_repo_commits",
        "level": "warn",
        "passed": false,
        "message": "补丁包含课程仓库自身的提交",
        "hint": "请先 git checkout <基线标签> 再生成补丁"
      }
    ]
  },

  "patch": {
    "files": [ { "path": "kernel/proc.c", "added": 12, "removed": 3 } ],
    "binary": false,
    "touches_protected": ["gradelib.py"]
  },

  "build": { "ok": true, "seconds": 41.2, "log_tail": "…最后 20 行…" },

  "tests": [
    {
      "id": "exit test",
      "title": "exit test",
      "points": 40,
      "earned": 40,
      "status": "ok",
      "seconds": 63.1,
      "message": null
    }
  ],

  "timing": { "total_seconds": 381.4, "qemu_boots": 3 },

  "artifacts": {
    "grade_log": "/out/grade.log",
    "qemu_log": "/out/xv6.out",
    "container_id": "a1b2c3d4"
  }
}
```

### 3.1 `stage` 取值

| stage | 含义 |
| --- | --- |
| `precheck_failed` | 预检未通过，未进入评测 |
| `build_failed` | 补丁已应用但编译失败 |
| `run_failed` | 编译通过但运行阶段失败（超时 / 崩溃） |
| `done` | 编译运行通过，`score` 有效 |
| `internal_error` | 平台自身故障 |

### 3.2 `failure_class` 取值

`verdict != "scored"` 时必填。

```
patch.empty                  补丁为空
patch.unparsable             不是合法 unified diff
patch.binary                 含二进制文件
patch.not_applicable         在当前基线上应用失败
patch.wrong_base             疑似基线不符
patch.contains_repo_commits  混入课程仓库自身的提交
patch.touches_protected      改动了评测资产（已被回挂忽略）
build.failed                 编译失败
run.timeout                  超时
run.panic                    内核崩溃
score.mismatch               解析分数与脚本自报不一致（平台自身问题）
internal.error               平台内部错误
```

> **注意**：`patch.*` / `build.failed` / `run.*` 属于**评测结果**，**不得重试**；
> 只有 `internal.error` / `score.mismatch` 才是**系统故障**，可以重试。

### 3.3 `precheck.checks[].code` 取值

```
patch.empty                  补丁为空
patch.unparsable             不是合法 unified diff
patch.binary                 含二进制文件
patch.too_large              补丁体积超限
patch.path_not_allowed       改动不在白名单内
patch.touches_protected      改动了评测资产
patch.contains_repo_commits  混入课程自身提交
patch.missing_new_files      新增文件未包含（疑似忘记 git add）
patch.wrong_base             基线疑似不符
```

`level` 取值：`error`（阻断评测）/ `warn`（允许评测但提示）。

---

## 4. 调用方（后端）的职责

- 生成唯一的 `submission_id` 并透传
- 提供补丁文件的**只读**挂载
- 读取 `--out` 指定的 JSON；**不要读 stdout 判断结果**
- 保存 `artifacts` 中的日志文件路径
- 把 `stage` / `failure_class` 映射为平台侧的提交状态

---

## 5. 实现方（评测）的职责

- **保证 `--out` 一定被写出**：即使平台内部崩溃，也要写出 `internal_error` 的 JSON
- 三级超时：单测试 / 整次评测 / 容器级
- 应用补丁后**强制回挂评测资产**（`gradelib.py`、`grade-lab-*`、`conf/lab.mk`、`user/*test.c` 等）
- 容器隔离：`--network none`、非 root、内存与 pids 上限
- 日志中不得出现完整学号等个人信息

---

## 6. 变更规则

`schema_version` 递增表示不兼容变更；新增可选字段不递增。
任何变更必须先改本文件，再改实现。

## 一、选型原则（按优先级）

1. **能结题优先** —— 大一立项、一年周期
2. **复用课程与既有资产** —— 课程仓库已提供 `Dockerfile`、`gradelib.py`、`grade-lab-*`、各实验基线 tag；前后端骨架复用开源中后台框架
3. **生态成熟、资料可检索** —— 遇到问题能搜到答案，降低卡壳风险
4. **可维护、可 fork** —— 项目开源，需要他人能接手并扩展其他课程

## 三、逐项选型

### 1. 后端语言：Python 3.11+

| 项 | 内容 |
| --- | --- |
| **理由** | ① 课程判分脚本 `gradelib.py` 本身就是 Python，解析器可直接对照其输出与数据结构；② 后端职责是 I/O 编排（收文件→查库→发队列→起容器→读输出→存结果），无算法密集点；③ Docker / 队列 / 数据库生态最完整；④ traceback 的排错成本远低于段错误 |

### 2. Web 框架：FastAPI

| 项 | 内容 |
| --- | --- |
| **理由** | ① **自动生成 OpenAPI / Swagger 文档**，前端联调刚需；② 原生 async，适配状态推送与并发查询；③ Pydantic 提供请求参数自动校验 |

### 3. 数据库：PostgreSQL（全程，不做 SQLite 过渡）

| 项 | 内容 |
| --- | --- |
| **选择** | **PostgreSQL 14** |
| **理由** | **所选若依 FastAPI 版原生支持 PostgreSQL**：仓库内提供 `docker-compose.pg.yml`（Postgres + Redis + 前后端全栈）、`requirements-pg.txt`、`.env.dockerpg`，且 `.env` 中 `db_type` 明确可选 `mysql` / `postgresql`。不是"能不能用"，而是"官方就提供 PG 版启动方式" |

### 4. ORM 与数据库迁移：SQLAlchemy 2.0（async）+ asyncpg + Alembic

| 项      | 内容                                                                                                                                                                         |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **选择** | 直接沿用模板既有方案                                                                                                                                                                 |
| **理由** | 模板 `requirements-pg.txt` 已锁定 `SQLAlchemy[asyncio]==2.0.51`、`asyncpg==0.31.0`、`psycopg2==2.9.12`、`alembic==1.18.5`；`config/database.py` 已实现多数据源与异步会话管理。**不自建 ORM 层，不与模板对抗** |
| **收益** | ORM 屏蔽方言差异；Alembic 使表结构变更可版本化、可回滚。业务表（用户/班级/实验/提交/判分记录/测试项结果）的建表与演进全部走迁移脚本，不手写 SQL                                                                                         |

### 5. 任务队列：PostgreSQL 表 + `FOR UPDATE SKIP LOCKED`

| 项 | 内容 |
| --- | --- |
| **选择** | 用数据库表作为评测任务队列，worker 以 `SELECT ... FOR UPDATE SKIP LOCKED` 领取任务 |
| **理由** | ① `SKIP LOCKED` 是 PostgreSQL 提供的标准工作队列原语，天然支持多 worker 无锁竞争；② **任务状态与业务数据（提交记录、分数、审计信息）处于同一事务**，不会出现队列与数据库的不一致；③ 可见性极好——排查时直接查表即可知道每个任务排到哪一步 |

### 6. 评测执行：Python worker + Docker CLI

| 项 | 内容 |
| --- | --- |
| **选择** | Python worker，通过 `docker` CLI 子进程驱动容器 |
| **理由** | 命令直观、日志易排查、抽象层少；需要流式控制时再改用 docker SDK |
| **隔离策略** | `--network none`、非 root、内存与 pids 上限、**三级超时**（单测试 / 整次评测 / 容器级） |
| **镜像来源** | Lab1–4：以课程 `Dockerfile` 为基础 + 隔离加固（去掉 `--privileged` 与 `--network=host`）；Lab5：需 FUSE 权限，**单独一套沙箱策略** |
| **双向驱动能力** | 判分脚本存在交互式场景（Lab5 的 `test.sh` 需输入选项），worker 必须同时具备**读取输出**与**写入 stdin** 的能力 |

### 7. 前端：RuoYi-Vue3-FastAPI 模板改造

| 项 | 内容 |
| --- | --- |
| **选择** | 基于若依 FastAPI 版（Vue3 + Element Plus + Vite + FastAPI）改造 |
| **理由** | 登录、权限、菜单、表格、分页、导入导出、代码生成器**全部现成**，且其后端即为 FastAPI，与既定选型一致 |
| **需自行开发** | 实验列表页、提交页、反馈详情页、班级成绩页（复用其 `el-table` 等组件） |
| **风险** | ① 社区项目，需确认 LICENSE 与活跃度（已确认所用仓库近期仍有提交）；② 模板自带大量本项目用不到的功能，需裁剪 |

### 8. Excel 导出：openpyxl（后端生成）

| 项 | 内容 |
| --- | --- |
| **选择** | 后端使用 `openpyxl` 生成，按实验维度导出 |
| **理由** | 统一数据口径、可控制样式、不受浏览器限制，且与「按实验导出」的需求直接对应 |

### 9. 部署：Docker Compose（校内 Ubuntu Server）

| 项 | 内容 |
| --- | --- |
| **选择** | Docker Compose 编排前端、后端、数据库、Redis 与评测 worker |
| **理由** | 模板已提供 `docker-compose.pg.yml`，在其基础上增加 worker 服务即可，便于迁移到学校服务器 |

### 10. 可选的 C++ 组件：`runner/patchcheck`

| 项      | 内容                                                      |
| ------ | ------------------------------------------------------- |
| **选择** | 用 C++ 实现补丁静态分析 CLI，由评测内核以子进程方式调用，输出 JSON          |
| **职责** | 解析 unified diff；路径白名单校验；二进制补丁检测；评测资产篡改检测；识别补丁中混入的课程自身提交 |
| **理由** | 纯文本计算、自包含、可单元测试、性能敏感，正是 C++ 的适用场景；同时保留团队的技术积累与答辩亮点      |
| **备注** | 属**可选组件**。若 S03 工期紧张，先用 Python 实现同功能版本，C++ 版后续替换        |

## 五、风险与对策

| 风险 | 对策 |
| --- | --- |
| 模板裁剪不干净，残留大量无用功能 | 先保证可用，裁剪放到 S07 |
| 依赖版本与模板不一致 | clone 后以模板的 `requirements-pg.txt` 与 `pyproject.toml` 为准锁定版本 |
| 本地开发未起数据库导致"跑不起来" | 从第一天起统一用 `docker compose -f docker-compose.pg.yml up -d` 起数据服务 |
| Lab5 的 FUSE 权限与隔离策略冲突 | 为 Lab5 单独定义沙箱策略档位（`sandbox_profile`），S07 专项验证 |
| C++ 版 patchcheck 拖慢 S03 | 该组件可选，先留调用接口，换用 Python 实现 |

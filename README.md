# RISC-V xv6 OJ

面向哈工大（深圳）操作系统实验课程的 **xv6 实验提交与自动评测平台**。

学生提交 `commit.patch` → 系统在隔离容器中复原补丁、编译内核、启动 QEMU、运行课程判分脚本
→ 解析结果，给出**逐项通过情况、得分与可读的失败诊断**。

---

## 这个项目解决什么问题

当前课程作业通过 Grader 平台提交 `commit.patch`，由教师逐个查看判断。实际运行中存在一个突出问题：

> **课程作业中，补丁本身的缺陷是学生得 0 分的主要原因，而教师难以逐个排查**——生成补丁时遗漏
> 步骤、未提交改动导致补丁为空、基线版本不一致、代码无法编译。

因此本平台的核心不是「打分」，而是：

1. **秒级预检**：在消耗评测资源之前，明确告诉学生「补丁哪里错了、怎么改」
2. **自动评测**：复用课程已有的 `grade-lab-*` 脚本，**不改变评分标准**
3. **教师减负**：班级成绩总表、筛选、导出 Excel

## 系统架构

```
┌──────────── 前端 web/（RuoYi-Vue3-FastAPI）────────────┐
│ 登录 · 实验列表 · 提交 · 反馈详情 · 班级看板 · 导出      │
└───────────────────────┬───────────────────────────────┘
                        │ 契约 C2：REST / OpenAPI
┌───────────────────────▼───────────────────────────────┐
│ 业务后端 services/api（Python + FastAPI）              │
│ 用户/班级/实验/提交/成绩 · 数据模型 · 任务队列 · 导出    │
└───────────────────────┬───────────────────────────────┘
                        │ 契约 C1：CLI + JSON
┌───────────────────────▼───────────────────────────────┐
│ 评测内核 services/judge（Python worker）                │
│ 预检 → 容器 → 复原补丁 → 回挂评测资产 → grade-lab → 解析 │
│       └─ 预检阶段调用 runner/（C++）补丁静态分析 CLI     │
└───────────────────────┬───────────────────────────────┘
                        │
        Docker 镜像（课程 Dockerfile + 隔离加固）
```

## 可扩展性

本平台的核心抽象是「**以补丁为提交物的实验**」，而不是「xv6 专用评测器」。
一个实验的全部差异都收在配置里，代码中不硬编码任何课程信息：

| 配置项 | 本课程取值 |
| --- | --- |
| 提交物类型 | Lab1–4：补丁（`commit.patch`）；Lab5：压缩包 |
| 代码仓库 + 基线 ref | 课程 xv6 仓库 @ 各实验的基线标签 |
| 评测镜像 | RISC-V 交叉工具链 + QEMU |
| 构建命令 | `make` |
| 判分命令 | `./grade-lab-<lab>` |
| 结果解析器 | 把判分脚本的输出转成结构化结果（**可替换**） |
| 沙箱档位 | 默认无特权；Lab5 需 FUSE 权限，单独一档 |

**接入一门新课程**通常只需要：写一份实验配置，若判分输出格式不同再实现一个解析器。
详细接入步骤见 `docs/04-spec/`（《如何新增一门课》，待补）。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 后端 | Python 3.11+ · FastAPI · SQLAlchemy 2.0(async) · Alembic |
| 数据库 / 缓存 | PostgreSQL 14 · Redis（模板自带，用于 JWT） |
| 任务队列 | PostgreSQL 表 + `FOR UPDATE SKIP LOCKED` |
| 评测 | Python worker · Docker CLI |
| 补丁静态分析 | **C++**（`runner/patchcheck`：解析 unified diff · 路径白名单 · 二进制检测 · 评测资产篡改检测），由评测内核以子进程调用 |
| 前端 | Vue3 · Element Plus · Vite（基于 RuoYi-Vue3-FastAPI 改造） |
| 部署 | Docker Compose（校内 Ubuntu Server） |

详见 `docs/02-design/技术选型说明.md`。

## 协作规范

- **分支**：`main` 保持可用；功能走 `feat/<S0n>-<简述>`，完成后合入 `main`
- **提交信息**：`<类型>(<范围>): <中文简述>`，类型 `feat|fix|docs|test|refactor|chore|ci`
- **合并**：至少 1 人评审；涉及接口变更必须同步更新 `docs/03-api/`
- **接口优先**：先改契约文档，再改代码

> 更完整的协作规范（分支保护、代码风格、评审清单）将在 `CONTRIBUTING.md` 中补充。
